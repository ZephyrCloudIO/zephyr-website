# Post-Migration Follow-Ups

Deferred low-priority items identified during the Rspress SSG migration (PR #228).
None of these block shipping — tackle as time allows. Effort is a rough guess (S = under an hour, M = a few hours).

## Dependencies & build

### 1. Remove the unused `@tanstack/react-router` dependency — S

- **Where:** `package.json` (`dependencies`), aliased in `rspress.config.ts` (`@tanstack/react-router` → `src/router-shim.tsx`).
- **Why:** The real package is fully aliased to the shim and never bundled, so it is a dead dependency.
- **Fix:** Remove it from `package.json`, run `pnpm install`, and confirm `pnpm typecheck` + `pnpm build` still pass.

### 2. Harden metadata serialization in the content generator — S/M

- **Where:** `scripts/generate-rspress-content.mjs` (`asJsObject` / `util.inspect`, used for `pageMetadata` and `src/generated/*-metadata.ts`).
- **Why:** Frontmatter is serialized with `util.inspect`. It only works today because every `date:` is a quoted string. An unquoted YAML date parses to a JS `Date`, which `inspect` prints unquoted (`2025-01-01T00:00:00.000Z`) — invalid JS that breaks the build. (Prettier now formats the output, but the underlying fragility remains.)
- **Fix:** Serialize with `JSON.stringify` (and a small reviver/format pass) or guard against non-primitive values, so a stray unquoted date can't break generation.

### 3. Guard against stale committed generated content — S

- **Where:** `docs/blog/*.mdx`, `docs/changelog/*.mdx`, `src/generated/*-metadata.ts` are committed and regenerated by `generate:rspress-content`.
- **Why:** The Prettier fix means regenerating no longer causes formatting drift, but if someone edits source content and forgets to regenerate, the committed output can go stale (typecheck still passes).
- **Fix:** Add a CI step that runs `pnpm run generate:rspress-content` then `git diff --exit-code` to fail on stale generated files. (Alternatively, gitignore the generated files and generate before typecheck/build — bigger change.)

## SEO / crawlers

### 4. Consolidate duplicate `User-agent: *` in robots.txt — S

- **Where:** `docs/public/robots.txt`.
- **Why:** There are two `User-agent: *` groups (one `Allow: /`, one `Crawl-delay: 1`). Duplicate records for the same agent are ambiguous per spec and parser-dependent.
- **Fix:** Merge into a single `User-agent: *` block.

### 5. (Optional) Prevent preview deployments from being indexed — M

- **Where:** `docs/public/_headers` / build config; applies to non-production Zephyr versions.
- **Why:** Previews serve `robots: Allow: /` with no `noindex`. They are protected today only by `rel="canonical"` → prod (a hint, not a hard directive). The Zephyr GitHub Action posts the preview URL on the PR, which is a discovery vector if the repo/PR is public.
- **Fix (only if certainty is wanted):** On non-prod builds, emit `X-Robots-Tag: noindex` (header), or a preview-only `robots.txt` `Disallow: /`, or a `<meta name="robots" content="noindex">`. Requires a build-time preview-vs-prod env flag (same artifact ships to both today). Low practical risk — canonical-to-prod already does the right thing.

## Landers

### 6. Lander gating is client-side only — M

- **Where:** `src/landers/LanderRoute.tsx`, `src/landers/runtime.tsx` (`mountLander`), gated by `ZE_PUBLIC_ENABLED_LANDERS`.
- **Why:** Disabled landers are still statically built, served, and crawlable; the redirect happens in JS after render (brief content flash), so the content is effectively public.
- **Fix:** If gating is meant to hide unreleased content, exclude disabled landers from the build/sitemap (e.g. skip generating their route, or enforce gating at the Zephyr edge) rather than relying on a client redirect.

## Analytics / CSP

### 7. CSP may block PostHog dynamically-loaded scripts — S

- **Where:** `docs/public/_headers` (`Content-Security-Policy` `script-src`).
- **Why:** `script-src` does not list a PostHog host. `posthog-js` is bundled so init works, but features that inject scripts at runtime (e.g. session replay's `recorder.js`) load from the PostHog host and would be CSP-blocked.
- **Fix:** If/when session replay or other dynamic PostHog scripts are enabled, add the PostHog host(s) to `script-src` (and verify `connect-src`).

## CI (workflow, out of this PR's scope)

### 8. `pull_request.yml` cleanups — S

- **Where:** `.github/workflows/pull_request.yml`.
- **Why:** For non-merged PRs it runs `pnpm run build` twice (double Zephyr deploy per run), and there is no `typecheck` step.
- **Fix:** Remove the duplicate build; add a `pnpm run typecheck` step before build.

## Nice-to-haves

### 9. Unknown routes return HTTP 200 instead of 404 — M (depends on Zephyr)

- **Why:** The Zephyr edge serves the SPA fallback (200) for unknown paths; the custom 404 renders client-side after hydration. Visible UX is correct, but the status code is 200.
- **Fix:** Configure the Zephyr edge to serve `404.html` with a real `404` status for unmatched routes (hosting-side config).

### 10. Blog hero image fallback — S

- **Where:** `src/components/pages/BlogArticlePage.tsx` (`<img src={post.heroImage}>`).
- **Why:** `post.heroImage` can be `undefined` when a post has no hero image, rendering a broken `<img>`.
- **Fix:** Fall back to the default OG image (or hide the `<img>`) when there is no hero image.
