Store release vs. OTA

The fix is done. Why are your users still waiting?

Store release

  1. Build a new binary
  2. Submit and wait for review
  3. Stage the rollout
  4. Wait for users to update
time to fix = store queue + update rateDays

Zephyr OTA

  1. Publish the new bundle
  2. Point production at it
  3. Users get it on next launch
time to fix = one releaseNext launch

Native code changes still go through the store. JS, UI and web-layer changes ship over the air.

Why teams use it

Release on your schedule, not the store's.

01

Fix it today

A production bug does not wait for a review queue. Publish the fix and users get it on next launch.

02

Roll back on the device

Every version stays available. Point the app at the last good one and users have it on next launch.

03

Choose who gets it

Send a version to an internal environment first, then to everyone. Same build, no rebuild.

How it works

Three steps. No new pipeline.

01Add Zephyr to your build

Add the Zephyr plugin to the bundler you already use for your React Native, Electron or Tauri app.

02Publish a version

Each build uploads as an immutable version. Nothing goes live until you say so.

03Release over the air

Point an environment at the version. Apps load it on next launch.
